Fine-Tuning of a Speech Recognition Model for Underrepresented African Languages

An end-to-end speech recognition project focused on fine-tuning Qwen3-ASR (1.7B parameters), a large speech foundation model, to improve transcription performance on low-resource African languages, including Luganda, Wolof, and Swahili.

Developed as part of the Google Waxal ASR Challenge, the project addresses the challenge of adapting modern AI models to languages with limited annotated data. I built a complete training pipeline covering data preprocessing, audio preparation, and model optimization, leveraging Parameter-Efficient Fine-Tuning (PEFT) with LoRA to efficiently adapt the model while reducing computational costs.

The project was developed using cloud-based GPU infrastructure, enabling scalable training, experimentation, and optimization of large-scale speech recognition models.

MOTIVATION & GOAL

Bridging the AI Gap for Low-Resource Languages

Why do existing AI voice assistants struggle with African speech, and how does this project solve the problem efficiently?

The Current Limitation

Most commercial speech-to-text models (like Whisper or standard LLMs) are trained predominantly on English, Mandarin, and European languages.

  • Phonetic Mismatch: When presented with African languages like Luganda or Wolof, standard models hallucinate or output unrelated words because they do not recognize the tonal acoustic patterns.
  • Data Sparsity: Low-resource languages lack the millions of hours of labeled audio usually required to train models from scratch.
  • Compute Bottleneck: Updating a massive 1.7-billion parameter model traditionally requires expensive supercomputer clusters that are out of reach for individual data scientists.

Technical Approach

Instead of retraining a model from scratch, I leveraged an advanced open-source audio foundation model (Qwen3-ASR) and specialized it using targeted fine-tuning.

  • Parameter-Efficient Fine-Tuning (LoRA): I froze the original model's general knowledge and attached lightweight, trainable "adapter" layers. I trained only 1.8% of the weights, reducing memory usage by 80%.
  • Custom Data Processing: I engineered a specialized audio-text pipeline that cleans, standardizes (16 kHz), and formats African speech recordings streamed directly from Hugging Face.
  • Cloud Training: The entire training and evaluation pipeline was conducted in a cloud GPU environment, ensuring scalable and cost-effective experimentation.

STEP 01 • DATA INGESTION

Streaming Audio from Hugging Face & 16 kHz Normalization

Instead of downloading heavy audio archives to local disk storage, the pipeline streams audio files directly from Hugging Face. Every recording is automatically resampled to a standardized frequency of 16,000 Hz, which is the required acoustic standard for neural network audio encoders.

Python Implementation 
def load_speech_dataset(language="lug", split="train"):
    # Stream dataset directly from Hugging Face cloud servers
    ds = load_dataset("google/WaxalNLP", name=f"{language}_asr", split=split, streaming=True)
    # Standardize all audio files to 16 kHz for neural network input
    ds = ds.cast_column("audio", Audio(sampling_rate=16000))
    return ds

train_dataset = load_speech_dataset(language="lug", split="train")
Key Benefit: Efficiently processes large-scale audio datasets streamed directly from Hugging Face in cloud environments.
EVALUATION METRICS

Model Performance & Results

How do we measure if a speech recognition model is actually improving? We evaluate transcription accuracy using Word Error Rate (WER) and Character Error Rate (CER).

Understanding Speech Recognition Metrics (In Plain English)

Unlike standard classification where we measure "accuracy", speech models are graded on error rates (lower percentage = better performance). A Word Error Rate (WER) of 18% means that out of every 100 spoken words, 82 were transcribed with absolute perfection. Character Error Rate (CER) measures spelling precision letter-by-letter, which is crucial for African languages with complex prefixes and suffixes.
